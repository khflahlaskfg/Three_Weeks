# أثر — نسخة مستقلة جاهزة لـ GitHub Pages

تتضمن هذه النسخة آخر تحديثات الهاتف، الرسالة المتحركة، فصل ٣ أسابيع، والتسجيل الأصلي.
لا تحتاج npm أو build أو خادم خلفي، ولا تعتمد على تسجيل الدخول إلى ChatGPT.

## الملفات

| الملف | وظيفته |
| --- | --- |
| index.html | النصوص والعناوين والرسالة ومسار التسجيل |
| style.css | الألوان والخطوط والتصميم وأحجام الهاتف |
| app.js | الحركات، فتح الظرف، تشغيل الصوت، ونصوص تبويبات الأسابيع |
| assets/anas-poem.mp3 | التسجيل الصوتي الحالي |
| .nojekyll | ملف فارغ لعرض الملفات مباشرة على GitHub Pages |

## تعديل الكلام

1. فك ضغط الملف أولًا واحتفظ بنسخة احتياطية.
2. افتح index.html في محرر نصوص برمجي، أو حرّره من GitHub عبر زر القلم.
3. ابحث عن الجملة التي تريد تغييرها، وعدّل الكلام فقط داخل الوسوم.
   مثال: <p>الكلام القديم</p> يصبح <p>الكلام الجديد</p>.
4. لا تحذف الوسوم أو خصائص id وclass أو علامتي الاقتباس حول الخصائص.
5. احفظ بترميز UTF-8. على Mac تجنّب حفظه بصيغة Rich Text أو إضافة .txt للاسم.
6. لتغيير كلام تبويبات «البداية / القرب / إحنا»: افتح app.js وابحث عن weekNotes.
   أبقِ علامات الاقتباس والفواصل والأقواس كما هي. النص الأول ظاهر أيضًا في index.html
   داخل العنصر week-note؛ عدّله في المكانين.
7. افتح index.html في المتصفح لمعاينة النسخة محليًا. الخطوط الخارجية تحتاج إنترنت.

## تبديل التسجيل — أسهل طريقة

- جهّز تسجيلًا بصيغة MP3 فعلية، وسمّه anas-poem.mp3.
- استبدل الملف الموجود داخل assets بالملف الجديد مع الحفاظ على نفس المسار والاسم.
- تغيير امتداد M4A إلى MP3 بالاسم فقط لا يحوّل الصوت؛ صدّره أو حوّله إلى MP3 أولًا.
- مدة التسجيل تتحدث تلقائيًا. يبدأ الصوت بعد الضغط على التشغيل.
- إذا أردت اسمًا آخر أو ملف M4A مدعومًا: ارفع الملف داخل assets، ثم عدّل قيمة src
  في عنصر audio داخل index.html إلى المسار الجديد، مثل assets/my-recording.m4a.
- على بعض الهواتف يتم التحكم بمستوى الصوت من أزرار الجهاز.
- بعد النشر، إذا ظهر التسجيل القديم، حدّث الصفحة. ويمكن استخدام اسم جديد وتحديث src
  لتجنّب النسخة المخزنة في المتصفح.

## نشر الموقع من واجهة GitHub بدون أوامر

1. أنشئ Repository جديدًا باسم مثل athar، واختر Public للطريقة العامة البسيطة.
2. فك ZIP وارفع محتويات مجلد athar-github، وليس ملف ZIP نفسه.
3. من Add file → Upload files، ارفع index.html وstyle.css وapp.js ومجلد assets كاملًا.
   يمكن رفع README.md أيضًا. يجب أن يظهر index.html مباشرة في جذر المستودع، لا داخل مجلد إضافي.
4. اضغط Commit changes. الفرع الافتراضي عادة main.
5. ملف .nojekyll قد يكون مخفيًا على Mac؛ يمكنك إنشاء ملف بهذا الاسم من Add file → Create new file
   وتركه فارغًا أو وضع تعليق نصي بسيط، ثم Commit changes.
6. افتح Settings → Pages.
7. تحت Build and deployment اختر Source: Deploy from a branch.
8. اختر الفرع main والمجلد /(root)، ثم Save.
9. انتظر اكتمال النشر؛ قد يستغرق حتى 10 دقائق. ستجد رابط الموقع في Settings → Pages → Visit site.
10. شارك رابط GitHub Pages، وليس رابط ملفات المستودع. الزوار لا يحتاجون تسجيل دخول.

## التعديلات بعد النشر

عدّل الملف من زر القلم في GitHub ثم Commit changes، أو ارفع النسخة المعدلة إلى نفس المسار.
لتغيير التسجيل افتح مجلد assets ثم ارفع الملف الجديد بنفس الاسم واستكمل Commit changes.
GitHub Pages يعيد نشر التحديثات، والرابط يبقى نفسه ما دام اسم الحساب والمستودع والإعدادات لم تتغيّر.

## لو لم يعمل شيء

- 404: تأكد أن index.html في الجذر وأن Pages يستخدم main و/(root)، وافحص حالة النشر.
- لا يوجد تصميم: تأكد من وجود style.css بجانب index.html وبنفس حالة الأحرف.
- لا يوجد صوت: تأكد من وجود assets/anas-poem.mp3 وأن الملف صوت صالح وليس اسمًا مغير الامتداد فقط.
- تغييرات غير ظاهرة: انتظر اكتمال النشر وحدّث الصفحة أو افتح نافذة خاصة.

## قبل مشاركة الموقع

الموقع المنشور للعامة والتسجيل قابلان للعرض والتحميل. المستودع Public يكشف الملفات وسجل تعديلات Git.
إزالة تسجيل من النسخة الحالية لا تمسحه تلقائيًا من تاريخ المستودع. تجنّب رفع محتوى لا تريد نشره.
نسخة GitHub مستقلة: تعديلها لا يغيّر نسخة ChatGPT Sites والعكس صحيح.
